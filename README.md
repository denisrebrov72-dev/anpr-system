# ANPR System — распознавание автомобильных номеров с управлением шлагбаумом

Десктопное приложение для автоматического распознавания российских автомобильных
номеров в реальном времени с интеграцией Arduino-шлагбаума, трекингом машин,
ручной верификацией оператором и тремя независимыми базами номеров.

Проект реализован как pet-проект с акцентом на **устойчивость распознавания
в реальных условиях** (движение, размытие, грязь на номере, разное освещение),
а не на «демо на одном идеальном кадре».

## Возможности

### Распознавание
- **Детекция номеров** через YOLOv8 (обучен на российских госномерах).
- **Распознавание текста** через CRNN-модель, квантизованную в INT8.
- **Трекинг машин** (ByteTrack) + **голосование по треку** — результат
  распознавания накапливается по кадрам, а не берётся с одного кадра.
  Это критично для устойчивости: одиночная ошибка OCR не портит итог.
- **Двухпроходный OCR**: сравнение «сырой» и «обработанной» вырезки
  (CLAHE + размытие), выбор лучшего результата по уверенности модели.
- **Валидация формата** номера по regex — мусорные распознавания отсеиваются
  до попадания в базы.
- **Флаг `needs_review`** для сомнительных случаев → оператор уточняет вручную.

### Интерфейс
- Тёмная тема, современный вид на `customtkinter`.
- **Экран «Детекция авто»** — единственный рабочий экран с камерой:
  - видео с рамками детекции (цвет зависит от статуса номера);
  - статус последнего распознавания;
  - превью вырезанного номера;
  - галочка **«Открывать шлагбаум для своих»** (можно отключить — тогда
    система работает как «наблюдение + журнал»).
- **Экран «Базы номеров»** — две колонки:
  - **Свои номера** (allowed) — кому открывать шлагбаум;
  - **Контроль** (watch) — кому играть тревогу.
- **Экран «Проверка»**:
  - журнал детекций с превью и полной информацией;
  - фильтр «только непроверенные»;
  - редактирование номера прямо в списке;
  - **экспорт журнала в CSV**;
  - глобальный поиск по всем трём базам.

### Три независимые базы
1. **`plates_log`** — журнал всех детекций с фото, уверенностями, статусами.
2. **`plates_allowed`** — «свои» номера. Открывается шлагбаум.
3. **`plates_watch`** — «контроль». Играется тревога + сохраняется фото.

### Интеграция с Arduino
- Управление шлагбаумом через **pyFirmata** (прошивка `StandardFirmata`).
- **Graceful degradation**: если Arduino не подключена или `pyfirmata` не
  установлен — приложение работает в режиме симуляции, не падает.
- Корректное завершение: при закрытии окна шлагбаум закрывается, порт
  освобождается.

## Архитектура

Проект разделён на слабосвязанные модули. Каждый отвечает за одну задачу:

```
main.py          — точка входа, создаёт окно, вешает on_close
  └── app.py     — ANPRApp: GUI + оркестрация (главный класс)
        ├── inference.py   — YOLO, CRNN, ANPR_Pipeline (весь ML)
        ├── database.py    — SQLite: log / allowed / watch
        ├── config.py      — пути, цвета, пороги, Arduino
        ├── dialogs.py     — ManualChoiceDialog, ManualInputDialog
        └── arduino.py     — ArduinoController (pyFirmata)
```

Такое разделение даёт:
- **возможность менять GUI отдельно** от ML-логики;
- **тестировать модули изолированно**;
- **лёгкую замену компонентов** (например, YOLO → RT-DETR, CRNN → TrOCR).

## Технологический стек

| Слой | Технология |
|------|-----------|
| **Детекция** | YOLOv8 (Ultralytics) |
| **Распознавание** | CRNN (CNN + BiLSTM + CTC), INT8-квантизация через `fbgemm` |
| **Трекинг** | ByteTrack (встроен в Ultralytics) |
| **ML-фреймворк** | PyTorch |
| **CV** | OpenCV |
| **GUI** | customtkinter (поверх tkinter) |
| **БД** | SQLite (WAL-режим) |
| **Железо** | Arduino + pyFirmata |
| **Звук** | `winsound` (Windows-only) |

**Особенности инференса:**
- YOLO работает на **GPU (CUDA)**, если доступен — ускоряет детекцию в 5–10 раз.
- OCR-модель работает **только на CPU**: INT8-квантизация использует бэкенд
  `fbgemm`, который не поддерживает CUDA. Это осознанный выбор ради
  3–4-кратного ускорения инференса и переносимости на любую машину.

## Как это работает

Пошагово, что происходит при обработке кадра:

1. **Захват кадра** — с веб-камеры или из видеофайла (`cv2.VideoCapture`).
2. **Каждый 3-й кадр** — идёт в обработку (остальные просто отображаются).
3. **YOLO-детектор** находит рамки номеров + **ByteTrack** присваивает
   каждой машине постоянный `track_id`.
4. **Вырезка номера** из кадра по рамке.
5. **OCR** через CRNN-модель → текст + уверенность.
6. **Голосование по треку**:
   - результаты по одному `track_id` накапливаются в буфере (15 кадров);
   - пока не набралось ≥5 голосов за один вариант — номер не считается
     распознанным (защита от единичных ошибок).
7. **Валидация формата** через regex → либо валидный номер, либо `needs_review`.
8. **Логика статуса**:
   - номер в `plates_watch` → **тревога** (звук + сохранение фото);
   - номер в `plates_allowed` → **открыть шлагбаум** (если галочка включена);
   - иначе → «нет доступа», просто в журнал.
9. **`needs_review`** → открывается инлайн-панель или `ManualChoiceDialog`:
   оператор подтверждает или вводит правильный номер вручную.
10. **Запись в журнал** — все данные + пути к фото + уверенности.

## Установка

### Требования
- **Python 3.10+**
- **Windows** (из-за `winsound`; на Linux/macOS потребуется замена звукового модуля)
- **Опционально**: NVIDIA GPU + CUDA — для ускорения детекции

### Шаги

1. Клонировать репозиторий:
   ```bash
   git clone https://github.com/ВАШ_ЛОГИН/anpr-system.git
   cd anpr-system
   ```

2. Создать виртуальное окружение:
   ```bash
   python -m venv venv_anpr
   venv_anpr\Scripts\activate      # Windows
   # source venv_anpr/bin/activate   # Linux/macOS
   ```

3. Установить зависимости:
   ```bash
   pip install -r requirements.txt
   ```

4. **Скачать модели** и положить их в:
   - `models/yolo/model/best.pt` — YOLOv8, обученный на российских номерах
   - `models/ocr_crnn/quant/crnn_ocr_model_int8_fx.pth` — квантизованная CRNN

   > Модели не входят в репозиторий из-за размера. Ссылки на скачивание —
   > см. [Releases](../../releases) или свяжитесь с автором.

5. (Опционально) Положить `fire-alarm.wav` в корень — звук тревоги.

## Запуск

```bash
python main.py
```

**Базовый сценарий:**
1. Открывается окно с боковой панелью и четырьмя экранами.
2. **«Базы номеров»** → добавьте пару тестовых номеров (свои и в контроль).
3. **«Детекция авто»** → «Выбрать видео» или оставить «Камера» → **Старт**.
4. Смотрите результат: рамки, статусы, звук тревоги, открытие шлагбаума
   (если `ARDUINO_ENABLED = True`).
5. **«Проверка»** → журнал, экспорт в CSV, поиск, редактирование.

## Интеграция с Arduino

### Что нужно
- Arduino Uno / Nano / Leonardo
- Реле-модуль (для реального шлагбаума) или встроенный светодиод (для теста)
- Arduino IDE

### Как настроить

1. **Залить Firmata**: `Arduino IDE → File → Examples → Firmata → StandardFirmata`.
2. Определить COM-порт: `Диспетчер устройств → Порты (COM и LPT)`.
3. В `config.py` указать:
   ```python
   ARDUINO_PORT = "COM3"      # ваш порт
   ARDUINO_PIN = 13           # пин, к которому подключено реле
   ARDUINO_ENABLED = True     # включить
   ARDUINO_OPEN_DURATION = 5.0  # сколько секунд держать открытым
   ```
4. Запустить приложение. Внизу экрана «Базы номеров» — статус подключения.

### Схема подключения реле
```
Arduino 5V   →  Реле VCC
Arduino GND  →  Реле GND
Arduino Pin  →  Реле IN (сигнальный)
```

> Внимание: большинство реле-модулей **активны низким уровнем**.
> Если ваш — такой, инвертируйте логику в `arduino.py`
> (`pin.write(1)` → `pin.write(0)` и наоборот).

## Сильные стороны

- **Устойчивое распознавание**: трекинг + голосование по треку — результат
  не портится от единичной ошибки OCR на одном кадре.
- **Двухпроходный OCR**: сравнение сырого и обработанного (CLAHE) результата —
  заметно повышает точность на плохих кадрах (ночь, блики, грязь).
- **Человек в цикле (human-in-the-loop)**: сомнительные номера не «угадываются»,
  а выносятся на ручную верификацию — критично для реальной эксплуатации.
- **Три базы** с чёткими ролями (лог / разрешено / контроль) — не смешивают
  разные сценарии.
- **Гибридный инференс** (YOLO на GPU + OCR на CPU) — оптимальный баланс
  производительности и переносимости.
- **Единая точка конфигурации** — все параметры собраны в `config.py`:
  пути к моделям, цвета, пороги, настройки Arduino.
- **Единый модуль нормализации** (`utils.py`) — одна точка правды для
  нормализации номеров, транслитерации кириллица ↔ латиница и валидации
  формата. Используется одновременно в `inference.py`, `database.py` и `app.py`.
- **Кроссплатформенный звуковой слой** (`sound.py`) — абстракция над
  `winsound` с graceful fallback: проект собирается и запускается даже там,
  где `winsound` недоступен (не падает с ImportError).
- **Graceful degradation**: нет Arduino / нет pyfirmata / нет GPU — работает.
- **Корректное завершение**: `on_close` останавливает камеру, отключает
  Arduino, освобождает порт.
- **SQLite с WAL-режимом**: параллельные чтения и записи не блокируют друг друга.
- **Экспорт в CSV** с UTF-8 BOM — открывается в Excel без плясок с кодировкой.
- **Модульность**: каждый файл делает одно. Легко менять части независимо.

## Ограничения и слабые стороны

Честный список того, что можно улучшить. Автор видит эти пункты и планирует
их закрыть в следующих итерациях.

- **YOLO и OCR работают в UI-потоке.** Из-за этого возможны фризы интерфейса
  при обработке тяжёлых кадров. **Решение:** вынести инференс в отдельный
  поток (`threading.Thread` + `queue.Queue` для возврата результатов).
- **Логирование через `print`**, а не `logging`. **Решение:** перевести на
  `logging` с ротацией файлов.
- **Нет автотестов.** **Решение:** покрыть юнит-тестами критичные функции
  (`normalize_plate`, `is_valid_russian_plate`, `_save_photos`,
  `is_allowed_plate`, `is_watch_plate`).
- **Журнал без пагинации** — показываются только последние 50 записей.
  **Решение:** кнопка «Загрузить ещё» или фильтр по датам.
- **Нет упаковки** в `.exe`. **Решение:** PyInstaller / Nuitka.
- **Модели не в репозитории.** Для удобства — выложить через Git LFS или
  HuggingFace.
- **Тестировалось только на Windows.** Linux/macOS не проверялись
  (звуковой слой использует `winsound`; на других ОС `SoundPlayer`
  корректно деградирует, но других особенностей не проверяли).
